### version 2.0.0 (unreleased)

#### Breaking

- `getCradleSpecs()`' `cradleActual.firstReferenceID` and `cradleActual.lastReferenceID` are renamed `firstRealReferenceID` and `lastRealReferenceID`. Their values are unchanged: the first and last cells in the cradle. To migrate, read `firstRealReferenceID` / `lastRealReferenceID`.

- `seedReferenceID` is the mount-time seed only. A change to the prop after mount no longer resets the list, and a new `fetchCells` identity no longer resets it either (the latest `fetchCells` is still the one every fetch calls). A host repositions the list with `calls.fetchCradleCells(id)` and clears it with `calls.fetchCradleCells('')`, as before; those are now the only ways to do either after mount, so one host action is one reset. Previously a prop-driven reset queued behind the host's own `fetchCradleCells` and overrode it, which left the list at the prop's row rather than the host's. A list cleared with `fetchCradleCells('')` now stays empty through a resize until the host seeds it again (it used to be re-seeded at the prop), and a list mounted with `seedReferenceID` null and seeded by `fetchCradleCells` is now reconfigured on a resize like any other (it used to be skipped)

- `fetchCells` is called with a start code in place of a direction: `fetchCells(startCode, referenceID, count)`, where `startCode` is `'at'`, `'after'` or `'before'` (it was `'seed'`, `'forward'` or `'backward'`). `startCode` names where the returned batch starts relative to `referenceID` in list order: `'at'` is inclusive (the batch begins with the reference item), `'after'` and `'before'` are exclusive, and `'before'` returns the items nearest the reference first, as the backward batch always had to. A host written against the old names fetches nothing, since no branch of its `fetchCells` matches, and the exported `FetchCells` type reports a comparison with an old literal as having no overlap. The `source` labels in the error and failed reports follow: `'fetchCells, at'`, `'fetchCells, after'` and `'fetchCells, before'`, with `arguments` holding the `startCode`. The opening `'at'` batch now goes into the cradle by the same path and under the same checks as an `'after'` batch (one loader; the separate seed path is gone): a cellPack that fails the check is reported as `cellPack must have valid id and component` with `source` `'fetchCells, at'`, the batch is then reported as `one or more errors found in fetched cellPacks. Loading aborted` and the fill ends, where the old seed path reported `seed cellPack ignored` and said nothing more. An empty `'at'` return still ends the opening fill, with nothing asked `'after'` or `'before'`

#### Added

- Placeholders. A list that outruns its rows shows placeholder cells: when the cradle is short at an end, the scroller stands placeholders in the positions it is waiting on, asks `fetchCells` for them, and fills each in place when the answer comes, so the list keeps scrolling while the host is slow, in both directions. Three new `operations` fields: `placeholderCap` (the most placeholders at each end; default a viewport and a half of cells, `Math.ceil(1.5 × cellsPerBand × visibleBands)`; `0` turns them off; a value that is not a number of 0 or more goes to `callbacks.error`, `source` `operations.placeholderCap`, and the default is used), `placeholder` (the host's own placeholder component, given `{context, index, direction, referenceID}`: `index` is the placeholder's distance from the host's rows, `0` nearest; a value that is not a component goes to `callbacks.error`, `source` `operations.placeholder`, and the default stands in) and `placeholderContext` (passed to every placeholder untouched; define it once or memoize it). The default placeholder is a gray *fetching…*, takes no size of its own, reads `context.text` as its text and shows none for `''`. A placeholder's id is the scroller's own, in the reserved form `_~_ph:<generation>:<serial>_~_`. The README's **Placeholders** section has the rules.
- `fetchCells` is given a fourth argument, `context`: `{attempt, signal}`. `attempt` counts the asks for the same cells, from `1`; `signal` is an `AbortSignal` that fires when the answer is no longer wanted (the ceiling, an ask let go, a structural call, a reset, the unmount). The scroller has at most one `fetchCells` call in flight; an ask names the host's last or first row as `referenceID` and the standing placeholders as `count`, never a placeholder's id and never an offset. The types `FetchContext` and `PlaceholderProps` are exported.
- `operations.placeholderSpreadRatio` (a number from 0 to 1, default `null`): in variable layout a placeholder's size on the axis is `min + ratio × (max − min)` of `cellDimensions`, and a row that fills it in place takes its own size. `null` and `0` leave a placeholder at the minimum, as before; uniform layout ignores the option. A value that is not a number from 0 to 1 is reported to `callbacks.error` and the default is used.
- `technical.FETCH_CEILING` (ms, default 5000): a fetch unanswered this long is dropped, its `signal` fires, a warning goes to `callbacks.warning` (`source` `fetchCells, at`, `fetchCells, after` or `fetchCells, before`; `attempt` in the pack), and the same cells are asked for again with `attempt + 1`, at every ceiling for as long as the placeholders stand. A late answer to a dropped attempt fills nothing. The opening `'at'` ask is under the ceiling too. A value that is not a positive number is the default.
- `callbacks.axisReferenceID(id, context?)`: when the cell at the axis is a placeholder the id is the placeholder's own and `context` is `{isPlaceholder: true, referenceID, direction}`, the host's row it stands beside and which side; a real row is reported with no `context`, as before. A host that keeps the axis for a restore reads `context?.referenceID ?? id`.
- `calls.has(referenceID, out?)`: a placeholder's id answers `true` while it stands and fills `out`, if given, with `{isPlaceholder: true, referenceID, direction}`; a reserved id is never reported as invalid.
- `getCradleSpecs()`' `cradleActual` carries `forwardPlaceholders`, `backwardPlaceholders`, `firstPlaceholderReferenceID` and `lastPlaceholderReferenceID` (the outermost cell at each end when it is a placeholder, otherwise `null`). `forwardCells`, `backwardCells` and `totalCells` count the host's cells; `firstRealReferenceID` / `lastRealReferenceID` name the host's first and last. `getCradleIDList()` leaves placeholders out, `removed` never names one, and `rs3attached` is not dispatched to one.
- `getCradleSpecs()`' `cradleActual.quiet` is `{forward, backward}`: at each end, `'end'` when the host's last answer there closed the run with nothing, `'failed'` when it closed it with a failure, and `null` when the end is open (nothing answered, or input, a structural call, a reset, a new cradle or a change of the cell at that end has asked again). It is a reading of the scroller's own end memory, the one the hold reads, so a host can tell a list that has stopped asking from one that was told there is nothing more.
- `getCradleSpecs()`' `cradleActual.endState` is `{head, tail}`, each `{inside, mark, slack, contentEdge}`: whether the end state stands at that end (the entries below), the scroll position at which the viewport's edge at that end rests (its forward edge at the tail, its start at the head), the slack the mark adds past the rows (a fixed amount in variable layout, `0` in uniform), and the scroll position of the cradle's edge at that end, placeholders included. `mark` and `contentEdge` are `null` outside the state, and `inside` reads `false` while the state's re-ask is out.

#### Changes

- Bug fix: a host's answer that arrived between a scroll and the scroller's response to it filled its rows out of sight. A scroll moves the viewport at once, and the scroller's response to it is an operation queued after. An answer that took its turn on the queue in between filled the run where the last operation had left it. On a long list under two wheel steps of 1,200 px, with the answer to the first step's ask of 130 rows arriving inside the second step's scroll event, all 130 rows filled behind the viewport, and the ask that followed was for a second run of 130 counted from their far end, so the user never saw those rows arrive. The second entry below gave every operation that moves the cradle the measure of an outrun cradle; the operations that only fill now take it too, before they fill. They are the operation that applies a host's answer, `fetchCradleCells()` with no argument, and the overflow pass at the head, where an outrun cradle is brought to the viewport in place of the pass's own adjustment. In the same case the cradle is now brought to the viewport first and the answer fills there (90 of its 130 rows in view, 30 just ahead of it, 10 just behind), and the ask that follows is for the 10 rows of room left ahead. Where the bring leaves no placeholder of the pending ask standing, the ask is let go as the entry below describes, and its answer, though it has arrived, fills nothing and is not read. The end state is unchanged, because an end that stands is not outrun: its re-ask is as it was, and `fetchCradleCells()` with no argument reads the ends as they stand when it is called, so with the viewport held past an end that stands it asks again at that end and brings nothing, and rows that answer end the state first, as before. A host has nothing new to handle (`workboxes` cbrief-325)
- Behaviour change: the pending `fetchCells` ask is let go when every placeholder it covers has been taken down. One fetch is out at a time, and an ask for an end the scroll had left stayed out until the host answered it or the ceiling dropped it, with the end the viewport stood at waiting behind it. After a mount and a hard flick forward on a host that takes 3 s, the forward ask went out 1.9 s into the scroll, though the trim had taken down the placeholders the backward ask covered 0.16 s in. Now a fill that finds the pending ask with no placeholder standing at its end fires its `signal`, clears its ceiling and sends the next ask. An answer to the ask let go fills nothing and is not read: an empty one is not taken as the end of the data. A run only partly taken down keeps its ask, and the answer fills what remains. The opening `'at'` ask and an ask the end state makes are never let go. The end let go of is asked again, as a new ask with `attempt` `1`, when placeholders stand there again. For a host: `signal` fires for one more reason, and the next call may arrive before the call let go has been answered.
- Bug fix: an operation on the cradle could end with the cradle behind the viewport, or under its potential, and nothing asked. The scroller's operations run one at a time on a queue, and what the viewport is owed after one (an outrun cradle brought to it, the room ahead stood and asked for) was done by some and left to a later operation by others. The tail-overflow pass filled before the shift it took, so the room that shift opened, or a cradle the scroll had outrun by then, waited for the next observation; a host's answer that took its turn on the queue in between filled its rows where the run stood, wholly behind the viewport, the scroller then asked past the data's end, and the empty answer carried the viewport to the tail, over rows the user never saw arrive. And `insert` and `replace` always, `remove` and `move` when they answered `false`, ended on their trim with no fill, which left the cradle short with nothing asked until the next scroll. Every queued operation that moves the cradle now ends the same way, inside its own turn of the queue: the outrun is measured as the operation runs, an outrun cradle is brought to the viewport (otherwise the operation's own shift is taken), and the fill follows. That is the two shifts, the bring, both overflow passes, the trim after a resize and the four structural calls. A host sees two differences. `insert` and `replace`, and a `remove` or `move` that answers `false`, are followed by the fill, which asks `fetchCells` for any room at the ends, as `remove` and `move` already did when they answered `true`; with placeholders off (`placeholderCap: 0`) the call resolves after that fetch, as theirs did. And with placeholders off the tail-overflow pass awaits the rows for the room its shift opened, as a forward shift does (`workboxes` cbrief-315)
- Behaviour change: after an empty or failed answer to an end's re-ask the viewport is brought back to the rows' edge plus the slack, at both ends and on a list of any length. The mark the end state keeps is made of rows alone. The first band of the placeholders standing for the re-ask is in the mark that is read only while they stand, so the first glide still ends with them in view; when the answer takes them down the mark is the rows' edge plus the slack again, and a second smooth scroll brings the viewport to it. Kept as a high-water value, the placeholders' band left the list resting one band past its last (or first) row with that room empty, and on a list shorter than its viewport the first row rested a band from the viewport's start. Only a gesture asks the end again: a scroll event past the mark, once it has faded for `SHORT_MOMENTUM_FADE`. The readings the scroller takes by itself (at the end of scrolling, when an answer stands the state up, when the last finger lifts, when a bring-back has been stopped) bring the viewport back and ask nothing. They are taken wherever the end stands, so also while its ask is out: a viewport taken out past the placeholders then is brought back onto them when that input has ended. One of them is never dropped for a bring-back in progress. The bring-back waits for the gesture to end and gives way to the user. A gesture has ended when no input has reached the list for the quiet window, which is `SHORT_MOMENTUM_FADE` (the window a gesture past the mark was already given; no new timer or constant) counted from the latest of the list's last scroll event, a wheel event along its axis, a touch's start, and the lifting of the last finger that began on the list. A reading the scroller takes by itself waits only for what is left of that window and then reads the viewport again, so an answer that lands when the list has been still that long brings the viewport back at once. No bring-back is started while a finger that began on the list is on the screen (the viewport is read when the last of them lifts, at `touchend` or `touchcancel`), and a running one is stopped at once, where it is, by a wheel along the list's axis or a new touch. A touch that only stops a bring-back may ask the end once more: the browser reports where it stopped the scroll with scroll events of its own, and where the end's ask has already been answered these are read as a gesture past the mark. Every bring-back takes its turn in the scroller's queue of changes to the list and reads the viewport again as its turn comes, so an ask or an answer ahead of it is applied first. An answer that lands while the first bring-back is still running turns it to the mark as it now reads, at once. The scroller's own repositioning of the cradle when scrolling stops is reported by a scroll event of its own, which was read as a gesture: where a bring-back had begun before that event arrived, the end was asked again and the bring-back was stopped by the repositioning that followed. That scroll event is no longer read as a gesture where it reports the repositioning alone, and the `scrollend` that comes with it no longer ends scrolling under a bring-back begun since. A scroll made just as scrolling stops, before its scroll event has been heard, is read at that stop as the gesture it is (the viewport is found away from the position it last reported), since the repositioning leaves its event nothing more to report. For that comparison the scroller's record of the scroll position is always what the viewport reports: after an instant scroll of its own (the repositioning, the entry's snap to the mark, the head's re-seat) it is read back from the viewport, where it was the position asked for, which a browser may round. `endState.mark` stands `slack` past `contentEdge` at rest (`workboxes` cbrief-311)
- Behaviour change: there is one end state, at whichever end the host has answered with nothing, and the head mirrors the tail. The head's hold is gone, as the tail's went in the entry below: the quiet window, the wheel cancelling at the head, and the re-seat of the viewport on the first row while the head's state stands. A gesture into the room before the first row now travels freely, is brought back to the head's mark with a smooth scroll, and asks the host `'before'` once more; rows answered there fill in place and the row the user was looking at does not move. The head's mark is the first row's edge less the slack (the fixed amount in variable layout, `0` in uniform); a list opened on its first row is not past it and is not moved, so it opens with no room before its first row. At both ends the re-ask now comes before the bring-back: with placeholders on, the placeholders of the ask are placed first and, while they stand, the mark reads past their first band, so the glide ends with them in view (before this the viewport was brought back first and the placeholders stood out of view past the mark). An empty answer takes them down, and the viewport is brought back to the rows' edge plus the slack (the entry above). On a list shorter than its viewport the tail's mark is never short of the viewport's rest at the head while the head's state (or its end memory) stands, in place of the test for a cradle with no rows behind the axis, which also read a head that had not been asked yet. `cradleActual.endState` reports both ends (the entry under Added) (`workboxes` cbrief-309)

- Behaviour change: a horizontal list's forward shift fires 5 px later, as a vertical one always has. The forward trigger stood at its band's start on a horizontal list (`left: 0`) and 5 px into it on a vertical one (`top: 5px`), and the shift fires when the trigger's far edge passes the viewport's start: after 3 px of travel into the band on a horizontal list, against 8 px on a vertical one. The backward trigger stands at the band's edge, so this travel is also the dead band between a forward shift and the backward one that undoes it. - Bug fix: the trim an axis standing inside a placeholder run defers was never taken when the run answered, only by the next shift. A fast scroll onto placeholders (a wheel burst, a fling) moves bands across the axis shift after shift while the trim behind it waits for the run's answer, and the answer placed its rows and trimmed nothing, so the cradle stood several times its potential at rest (240 cells against a potential of 54 after a burst forward and back, on a variable list of three cells per band) until another shift. The answer now takes the trim itself, at each of its three ends: after rows are placed, and after the run is taken down on an empty or a failed answer, before the fill that follows. It is the same trim, so an answer that leaves the axis inside what is left of the run waits again, the run's anchor stays, and the head keeps the bands a put-back would show. `removed` names the rows it takes, as for any trim.
- Behaviour change: the end of the data at the tail is a state the scroller enters once and stays in, not a snap and hold taken at every crossing. It replaces the tail's hold described in the entries below (the quiet window and the wheel cancelling at the tail are gone with it; the head keeps its hold, its quiet window and its cancelling, since a list starts at the head and the viewport is already at its own stop there). The scroller enters the state when the host answers `'after'` with nothing (or fails to answer) while the viewport reaches past the last row, or when the viewport arrives there with that answer already given: the viewport is snapped so that its forward edge rests at a mark, the content's end plus a small fixed slack in variable layout (none in uniform), and held for the momentum fade to stop the gesture, once. Inside the state the scrollblock is left as it is (it is never sized to the content), the tail overflow trigger is not consulted, and the cradle does not follow the viewport past the end: the outrun, the forward shift and the tail overflow stand aside while the end stands, and through its re-ask (the head block is anchored at the axis, so a re-ask's placeholder bands shifted through it and withdrawn would have dropped the rows by their height; and the outrun's open-fetch bet that rows are coming is not one the re-ask's own fetch makes). The mark follows the content: on when it grows, kept when it shrinks, and reset to the content's end whenever the viewport's forward edge comes back above it. A gesture past the mark is not fought while it runs: once it has faded (`SHORT_MOMENTUM_FADE` from its last scroll event) the viewport is brought back to the mark with a smooth scroll and the tail is asked once more, with placeholders standing for the ask as the feedback; rows answered leave the state, and an empty answer stands it up again on the same mark. The state goes with the end memory (a structural call, a reset, a new cradle, the last row leaving the cradle). Horizontal lists mirror it. Before this a wheel into the end of a variable list was snapped back at every crossing and the viewport fought for the quiet window, and a gesture past the end re-consulted the overflow trigger each time (`workboxes` cbrief-282)
- Bug fix: with placeholders off (`placeholderCap: 0`) the inline fill asked an end the host had already answered empty at again on every pass, since the fill read only its own `moreExpected` and not the end memory. Previously neither was checked, and the scroller's readers split by the literal each tested, so `'Vertical'` was a horizontal list to the layout and a vertical one to the check of `cellDimensions`, with nothing reported. Ruled (Henrik, 2026-10-20): *"I agree with q1, 2, 3 leans"*, on the lean of checking both in `spacing`'s shape, under the earlier ruling that *"any internal substitution of inputs needs a warning"*
- Behaviour change: a report with no callback to take it goes to the console, on every channel, named by the scroller: an `error` to `console.error`, a `warning` or a `failed` batch to `console.warn`, as `react-super-simple-scroller (<scrollerName>): <source>: <message>` with the report's object beside it. Previously `error` and `warning` were dropped in silence, as was `failed`, while the queue's stall and the call after unmount each wrote a console line of its own; those two now go through the same reporter, so their lines carry a `source` like the rest. The four warnings in the calls (a `remove`, `move`, `replace` or `dispatchEvent` whose target the cradle does not hold), the call after unmount and the three batches cut to `count` now go through one reporter per channel, as errors did from 2.0.0's first change: each reads its callback when it reports and catches one that throws (it goes to `console.error`). `failed` keeps its object (`{source, message, excessList, timestamp}`). The hooks no longer keep the callbacks of the render they were made in, so `removed` is read when the cell is removed too. Ruled (Henrik, 2026-10-20): *"I agree with q1, 2, 3 leans"*, on the lean of one policy, in the reporters, with `failed` in the `warning` class

Ruled (Henrik, 2026-10-20): *"I agree with q1, 2, 3 leans"*, on the lean of comparing by value, as `spacing` does

The answer that stands the state up again now reads the viewport as a scroll event does and schedules the bring-back; that bring-back does not ask the host again

It now reads the head as it stands when it runs, as the outrun recovery does, and when the answer has put the head's edge back before the viewport it moves only the rows a backward shift would.

- Bug fix: a cradle could stand over its potential at rest in two places, until the next shift trimmed it. The axis's transform carries it, written in the scroll event, and no wheel or touch input is taken over. Ruled (Henrik, 2026-11-10): *"the elastic travel and pullback should be minimal, like an elastic, not as expansive as an expandable list"* (`workboxes` B904, cbrief-312)

The ask that a gesture past an end's mark sends places nothing, the mark is the rows' edge (plus the tail's slack) throughout, and the rows it answers with are added at the end, with the rows already standing unmoved; they used to fill placeholders that were placed for the ask, and the mark read past the placeholders' first band while they stood.
